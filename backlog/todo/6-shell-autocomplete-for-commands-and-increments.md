# shell autocomplete for commands and increments

## Scope

### Goal

Provide shell tab-completion for `backlog` so human users get completions for
sub-commands and, especially, for increment numbers/names derived from the
live backlog state.

### Context

`backlog` has a stable set of sub-commands (init, new, start, done, list,
help). Increments are files named `NNNNN-slug.md` under backlog/{todo,
in-progress,done}/. When a user wants to `start` or `done` a specific
increment they currently must recall/type the number or name; completion would
surface the valid candidates per state (e.g. `done` completes against
in-progress items). Unknown: which shells (bash, zsh, fish) to target first.

### Done When

- [ ] Tab-completion for `backlog` sub-commands in at least one shell.
- [ ] `backlog start <TAB>` completes against todo increments; `backlog done
      <TAB>` against in-progress increments.
- [ ] Completion honours `--done`/`--grep` etc. where relevant and falls back
      cleanly when no candidate exists.
- [ ] Generated completions are easy to install (documented command or script).

### Uncertainties

- [ ] Which shells are worth supporting (bash/zsh/fish) and how much each
      needs.
- [ ] Whether completions are generated by the binary itself (e.g. `backlog
      completions` / completion subcommand) or shipped as static scripts.

### Notes and analysis

Increment names are slugified (lowercase, kebab-case) and prefixed with a
5-digit id; completion should match both number and slug against the
state-appropriate dir. Related: the parallel-drafting id collision from this
session (00004 shared by three increments) suggests a `new` could benefit from
completion too - no, that is selection, not drafting; but serialising/guarding
`nextId` against races is worth a note in the bug increment (00005).
